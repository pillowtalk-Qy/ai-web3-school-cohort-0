## Human Confirmation and Safety Boundary / 人工确认与安全边界

Throughout Week 1, I used this boundary:

- AI / Agent can read public materials, organize notes, draft proof, explain transaction fields, check Git status, and run read-only verification.
- AI / Agent must not hold or request a private key, seed phrase, token, cookie, session, or `.env` content.
- AI / Agent must not sign transactions, approve spending, transfer assets, deploy contracts, push to GitHub, or submit WCB proof without explicit human confirmation.
- Wallet signing, token approval, transfer, contract write, contract deployment, GitHub publishing, and WCB proof submission are all human-confirmed actions.

This boundary is important because AI x Web3 workflows combine language-model planning with financial and permissioned systems. The safest Week 1 pattern is:

```text
AI prepares and explains.
Tools verify public facts.
The wallet displays the action.
The human confirms or rejects.
The chain records the result.
The public repo stores a sanitized proof.
```

## Week 1 Reflection / 第一周复盘

Week 1 helped me connect AI-assisted learning with Web3's verification culture.

My main takeaways:

- A public GitHub repo can become a durable proof-of-work surface.
- AI is useful for organizing learning, turning tasks into checklists, and preparing reviewable public records.
- Web3 proof should be verifiable through public artifacts: commits, Markdown files, explorer links, RPC results, contract addresses, transaction hashes, and live demos.
- The closer a task gets to wallets, signatures, token approvals, transfers, or platform submissions, the more important the human confirmation boundary becomes.
- A good AI x Web3 workflow is not "AI controls everything." It is "AI helps prepare, explain, and verify while the human keeps authority over high-risk actions."
