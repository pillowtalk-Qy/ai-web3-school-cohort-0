## 进阶内容笔记

### 1. Vitalik Buterin - What I would love to see in a wallet

链接： https://vitalik.eth.community/general/2024/12/03/wallets.html

这篇文章讨论了理想钱包应该具备的能力，包括跨 L2 支付、社交恢复、多签、Session Keys、隐私余额和 dapp 安全。它让我意识到钱包不只是签名工具，而是用户权限、安全策略和链上体验的入口。

和 Week 1 的关系：Agent Wallet 如果要替用户执行任务，就必须先解决权限管理、风险控制和恢复机制。

我还不理解的问题：ERC-7715、ERC-4337、EIP-7702 这些钱包相关标准之间如何组合落地？

This article discusses what an ideal wallet should support, including cross-L2 payments, social recovery, multisig, session keys, private balances, and dapp security.

My takeaway is that a wallet is not just a signing tool. It is the entry point for user permissions, safety policies, and onchain experience.

Relation to Week 1: if Agent Wallets are expected to execute tasks for users, they must first solve permission management, risk control, and recovery.

Open question: how do ERC-7715, ERC-4337, and EIP-7702 combine in real wallet products?

### 2. Z.AI / GLM - GLM-4.5 Overview

链接： https://docs.z.ai/guides/llm/glm-4.5

GLM-4.5 面向 Agent 应用，在工具调用、浏览、软件工程、前端开发和长上下文上做了优化。它反映的趋势是：模型不只是回答问题，而是可以接入工具、代码环境和外部 API，成为执行任务的核心组件。

和 Week 1 的关系：AI coding workflow 和 Web3 builder 训练密切相关。更强的模型能力可以让新人更快做出 demo，但也会提高对工具调用安全性的要求。

我还不理解的问题：模型评测中的工具调用能力，如何迁移到真实 Web3 场景里的钱包、合约和交易操作？

GLM-4.5 is designed for Agent applications and optimized for tool use, browsing, software engineering, frontend development, and long context.

My takeaway is that models are no longer only answer engines. They can connect with tools, code environments, and external APIs to become execution components.

Relation to Week 1: AI coding workflow is closely connected to Web3 builder training. Stronger models can help beginners build demos faster, but they also increase the need for tool-use safety.

Open question: how can benchmarked tool-use ability transfer into real Web3 scenarios involving wallets, contracts, and transactions?

### 3. Cobo - Agentic Wallet

链接： https://www.cobo.com/post/cobo-launches-agentic-wallet-how-ai-agents-interact-on-chain

Cobo 的 Agentic Wallet 方向强调 MPC 钱包、人机授权协议和可复用的链上操作能力。它把钱包从“用户手动签名工具”推进到“可配置权限、可审计、可撤销的 Agent 执行层”。

和 Week 1 的关系：这正好对应 Agent Wallet、AI payment 和链上自动化执行。Agent 不能无限制地控制资产，必须有清晰的授权范围和安全边界。

我还不理解的问题：MPC 钱包和 Account Abstraction 钱包在 Agent 场景中分别负责什么？它们是替代关系还是互补关系？

Cobo's Agentic Wallet direction emphasizes MPC wallets, human-agent authorization protocols, and reusable onchain operation capabilities.

My takeaway is that wallets are moving from manual signing tools toward configurable, auditable, and revocable execution layers for Agents.

Relation to Week 1: this maps directly to Agent Wallet, AI payment, and automated onchain execution. Agents should not have unlimited control over assets; they need clear authorization scope and safety boundaries.

Open question: in Agent scenarios, what roles do MPC wallets and Account Abstraction wallets each play? Are they substitutes or complements?

### 4. GoPlus - Transaction Risk Detection

链接： https://x.com/GoPlusSecurity

GoPlus 的核心价值在于把地址、合约、Token、授权、签名和交易风险前置到用户或 Agent 执行之前。对 AI Agent 来说，这类安全层很重要，因为 Agent 可能会自动调用合约、授权资产或执行跨链操作。

和 Week 1 的关系：Agent 执行能力越强，越需要交易前模拟、风险评分和自动拦截机制。安全不应该只发生在资产已经损失之后。

我还不理解的问题：如果风险检测系统出现误报或漏报，Agent 应该如何决定继续执行、暂停执行，还是请求人类确认？

GoPlus brings address, contract, token, approval, signature, and transaction risk detection before users or Agents execute actions.

My takeaway is that this kind of security layer is important because Agents may automatically call contracts, approve assets, or perform cross-chain operations.

Relation to Week 1: the stronger an Agent's execution ability becomes, the more it needs pre-transaction simulation, risk scoring, and automatic blocking. Security should happen before assets are lost.

Open question: if a risk detection system has false positives or false negatives, how should an Agent decide whether to continue, pause, or ask for human confirmation?

### 5. Phala Network - Confidential AI and TEE

链接： https://x.com/PhalaNetwork

Phala 关注 TEE、可信执行和隐私计算，这对于 AI Agent 很关键。因为 Agent 不只是生成文本，还可能处理私钥权限、用户数据、交易策略和敏感指令。可信执行环境可以让用户更清楚地知道 Agent 在哪里运行、执行了什么，以及是否被篡改。

和 Week 1 的关系：它连接了 AI Agent 的运行环境、安全边界和隐私保护。Agent 不仅要“能执行”，还要“可验证地执行”。

我还不理解的问题：TEE 的远程证明如何与钱包授权、智能合约验证和前端用户体验结合？

Phala focuses on TEE, trusted execution, and privacy-preserving computation. This matters for AI Agents because Agents may handle private data, asset permissions, trading strategies, or sensitive instructions.

My takeaway is that users need to know where an Agent runs, what it executes, and whether the runtime has been tampered with.

Relation to Week 1: this connects AI Agent runtime, security boundary, and privacy protection. An Agent should not only be able to execute; it should execute verifiably.

Open question: how can TEE remote attestation connect with wallet authorization, smart-contract verification, and frontend UX?

### 6. Bruce Xu - 我想对抗数字世界的失控

链接： https://x.com/brucexu_eth/status/2049767573278068872

Bruce 这篇内容把密码朋克、Ethereum/Web3、开源和 AI 放在同一条主线上：人在数字世界里应该拥有更多控制权，而不是完全依赖平台账号、中心化支付、算法推荐和封闭 AI 产品。它讨论的不是某个单点技术，而是身份、资产、数据、协作和 AI 工作流能否被个人掌握。

和 Week 1 的关系：这篇很适合作为 AI x Web3 的价值观背景。Agent Wallet、账户抽象、隐私、安全和开源协作，本质上都是在回答同一个问题：AI 时代的个人如何拥有可验证、可迁移、可退出的数字系统？

我还不理解的问题：如果个人要拥有自己的 AI Agent、记忆层、工具层和链上资产控制权，普通用户需要什么样的产品抽象，才不会被复杂的密钥、权限和基础设施门槛挡住？

This post connects cypherpunk values, Ethereum/Web3, open source, and AI around one theme: people should have more control in the digital world instead of fully depending on platform accounts, centralized payments, algorithmic feeds, and closed AI products.

My takeaway is that this is not about one technical point. It is about identity, assets, data, collaboration, and AI workflows being controllable by individuals.

Relation to Week 1: this is a useful value background for AI x Web3. Agent Wallet, account abstraction, privacy, security, and open-source collaboration all answer a similar question: how can individuals have verifiable, portable, and exit-capable digital systems in the AI era?

Open question: if individuals want to own their AI Agent, memory layer, tool layer, and onchain asset control, what product abstraction can make this usable without overwhelming users with keys, permissions, and infrastructure complexity?

## 接下来想继续观察的问题

### Agent Wallet 的权限模型

Spending Limits、Session Keys、MPC、Account Abstraction、人类确认这些机制如何组合？一个真正面向个人主权的 Agent Wallet，应该如何让用户拥有资产控制权，同时避免被复杂的密钥、授权和安全规则吓退？

How can spending limits, session keys, MPC, account abstraction, and human confirmation work together? What should a truly personal-sovereign Agent Wallet look like if it needs to keep users in control while hiding key-management and security-rule complexity?

### 个人可控的 AI x Web3 系统

AI Agent、钱包、身份、数据、记忆层、工具层和开源协作能否组合成一个可验证、可迁移、可退出的数字系统？交易模拟、风险检测、隐私保护、TEE 和 intent routing 在其中分别承担什么角色？

Can AI Agents, wallets, identity, data, memory layers, tool layers, and open-source collaboration form a verifiable, portable, and exit-capable digital system? What roles do transaction simulation, risk detection, privacy protection, TEE, and intent routing each play in that system?
