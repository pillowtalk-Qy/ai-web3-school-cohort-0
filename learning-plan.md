# Learning Plan

## Strategy

Although I already have some AI and Web3 background, I will follow AI x Web3 School from the beginning.

The purpose is to rebuild my foundation, identify gaps, adapt to the cohort learning rhythm, and turn learning into visible notes, task proofs, experiments, and feedback.

## Phase 0: Setup and Orientation

- Read the AI x Web3 School Handbook.
- Set up the GitHub learning repository.
- Define public/private boundaries for the repository.
- Create reusable templates for daily notes, tasks, experiments, Handbook feedback, and Hackathon ideas.
- Prepare a basic workflow for working with a Learning Agent.

## Phase 1: AI Foundation Review

Focus areas:

- LLM basics
- Prompting
- Context engineering
- RAG
- Agent workflows
- Tool use
- Evaluation and iteration

Expected outputs:

- Daily learning notes
- Prompt and agent workflow experiments
- Questions and gaps found during review

## Phase 2: Web3 Foundation Review

Focus areas:

- Wallets
- Networks
- Transactions
- Signatures
- Smart contracts
- Account abstraction
- Security basics

Expected outputs:

- Testnet-based experiment notes
- Task proofs
- Glossary and concept review notes
- Security boundary reminders

## Phase 3: AI x Web3 Bridge

Focus areas:

- Agent and wallet workflows
- AI-assisted contract interaction
- Verifiable records
- Identity and permissions
- Payments and settlement
- Onchain/offchain coordination
- Governance and collaboration patterns

Expected outputs:

- Small experiments that connect AI workflows with Web3 primitives
- Handbook feedback
- Early Hackathon problem exploration

## Phase 4: Hackathon Preparation

Focus areas:

- Problem exploration
- User definition
- AI component
- Web3 component
- MVP scope
- Demo path
- Submission materials

Expected outputs:

- Hackathon idea notes
- Demo plan
- Risk list
- Final submission draft

## Review Rhythm

- Daily: write a short learning note.
- Weekly: review gaps, update the learning plan, and summarize progress.
- Before publishing: manually review content for privacy and security risks.
- Before commit or push: confirm with a human reviewer.
