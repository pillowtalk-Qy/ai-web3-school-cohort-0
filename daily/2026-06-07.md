## Hackathon Direction / 黑客松方向

今天之后，我更明确地感觉到，`AI Wallet Clear Intent Guard` 的 Demo 前端不能只是一个工具界面，也应该是一条展示路径。

它至少要让评委很快看懂：

```text
User intent
-> Agent proposal
-> Payment / Packet facts
-> Guard review
-> Risk label
-> Human confirmation
-> Audit proof
```

前端页面需要承担两件事：

1. 让用户相信这是一个真实痛点。
2. 让评委看到技术框架如何落到一个可操作流程里。

今天看的夺冠项目提醒我，Demo 不一定要把所有能力都展示出来。更重要的是让第一条路径足够清楚、视觉层级足够稳定、结果反馈足够明确。

English companion:

The frontend should not be only a tool surface. It should be a guided presentation path: user intent, agent proposal, payment or packet facts, Guard review, risk label, human confirmation, and audit proof.

## Rebuilt Understanding / 重新建立的理解

- 黑客松 Demo 的前端不是包装层，而是评委理解项目的入口。
- 好的页面应该先服务理解，再服务炫技。
- 第一屏需要快速回答 problem、user、action 和 outcome。
- Demo flow 需要像一个故事：用户意图出现，Agent 提议动作，Guard 发现风险或一致性，用户做确认，最后留下 proof。
- 对 `AI Wallet Clear Intent Guard` 来说，最重要的 UI 可能不是聊天框，而是 review card：把 intent、facts、policy decision、risk label 和 proof 放在一起。
- 休息日也可以产生有效输入：不是所有推进都必须是写代码，有时观察别人如何展示也会改变自己的构建方式。

- Hackathon frontend is not just packaging; it is the entry point for judging.
- A good page should first help people understand, then impress them technically.
- The first screen should answer problem, user, action, and outcome quickly.
- The most important UI for this project may be the review card, not the chat box.
- Rest days can still create useful product input through observation.
