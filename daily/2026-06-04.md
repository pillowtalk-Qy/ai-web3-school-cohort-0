`Mandate` 可以理解成基于用户原始任务意图的任务级预算授权。用户不是每一笔 API 调用都反复确认，而是对一个完整任务目标和预算上限授权。Agent 后续所有支出都必须落在这个任务范围和预算边界内。

```text
Rule-based filtering
-> Natural language intent matching
-> AI model auxiliary evaluation
```

```text
task intent
budget

payment facts
risk signals
audit trail
```

English companion:

The financial harness session introduced Mandate as a task-level spending authorization. It binds user intent, budget, merchant or API scope, and validation rules. This adds a task-budget layer above individual payment review.

## Hackathon Direction / 黑客松方向

今天之后，`AI Wallet Clear Intent Guard` 的 review surface 更清楚地分成三层：

```text
Mandate = task-level intent and budget
Packet = permission package for agent execution
Payment = concrete transaction or API call
```

这三层不是互相排斥，而是可以形成一个更完整的审查链：

```text
User creates task mandate
-> Agent proposes permission or payment
-> Guard extracts deterministic facts
-> Guard checks budget and scope
-> Guard checks semantic intent match
-> Guard flags risk
-> User confirms or rejects
-> Audit proof is recorded
```

和 6 月 3 日 Cobo Wallet 的 `Packet` 机制放在一起看，今天的 `Mandate` 给了另一个关键补充：

```text
Cobo Packet = execution permission boundary
Financial Mandate = task and budget boundary
x402 payment = concrete payment execution surface
```

这让我更清楚地看到，第一版 demo 可以不只是“解释交易”，而是解释：

- 这笔支付属于哪个任务？
- 是否在预算内？
- 是否在商户 / API 范围内？
- 是否符合用户原始意图？
- 是否需要人工确认？
- 执行后如何留下审计 proof？

English companion:

The project now has a clearer three-layer model: Mandate for task intent and budget, Packet for execution permission, and Payment for the concrete transaction. A strong demo can compare these layers before signing or execution.

- demo 的第一张 review card 应该能同时展示 intent、facts、policy / mandate decision、risk label 和 audit proof。

- The hackathon is now in delivery mode; expanding the idea further may weaken execution.
- Mandate controls task and budget boundaries; Packet controls execution permission; Payment exposes concrete transaction facts.
- Good Agent payment UX sits between repeated manual approvals and unlimited agent spending.
- Deterministic rules should come first, semantic matching second, and AI review only for uncertain cases.
- The first review card should show intent, facts, policy or mandate decision, risk label, and audit proof.
