### Qy Knowledge Hub Follow-up / Qy Knowledge Hub 后续行动

- 在 Hermes 课程笔记的 `Follow-up Actions` 中记录 Qy Knowledge Hub。
- Qy Knowledge Hub 是正在搭建的个人知识处理中枢，用于把网页、社交平台、笔记和工作流里的信息进行整理、分类、风险过滤和人工审核，再沉淀成可信知识、内容素材或行动队列。

- 设计原则：
  - 本地优先。
  - 安全优先。
  - 外部信息不会直接触发操作。
  - 不自动打开链接、下载文件、执行命令、授权平台或发布内容。
  - 重要动作都需要人工确认。
- Hermes 在这个系统里更像受控智能协作助手，帮助维护本地流程、整理知识结构、生成检查结果和 Dashboard，并协助规划后续 Notion、Obsidian 和社交平台集成。

- Recorded Qy Knowledge Hub in the Hermes class note's `Follow-up Actions`.
- Qy Knowledge Hub is a personal knowledge-processing hub for organizing, classifying, risk-filtering, and manually reviewing information from web pages, social platforms, notes, and workflows before turning it into trusted knowledge, content material, or action queues.
- Current progress is about 60%.
- Design principles:
  - local-first
  - safety-first
  - external information does not directly trigger actions
  - no automatic link opening, file downloading, command execution, platform authorization, or publishing
  - important actions require human confirmation
- In this system, Hermes acts more like a controlled intelligent collaborator that helps maintain local workflows, organize knowledge structures, generate review results and dashboards, and plan future Notion, Obsidian, and social-platform integrations.

## Rebuilt Understanding / 重新建立的理解

今天之后，我把这些理解重新梳理了一遍：

- AI 工具不应该只按品牌名理解，而应该按使用层级分类：聊天、开发环境、终端 Agent、模型平台、通用助手底座。
- Hermes 的优势不是替代专业开发工具，而是把模型、工具、记忆、skills 和消息平台连接成长期工作流。
- 消息网关很方便，但会放大权限和误触风险，因此白名单、唤醒词、角色隔离和人工确认很重要。
- Skills 的意义在于把重复任务变成可复用流程，这和学习仓库、知识库、个人工作流维护高度相关。
- Qy Knowledge Hub 的核心价值，是把外部信息先变成可审核的数据，再沉淀为可信知识资产，而不是让外部平台反向控制系统。
- ZK trading system 让我重新看到，链上交易系统不是单点技术问题，而是证明、见证数据、排序、预言机、DA、成本和用户行为共同组成的系统问题。

After today, I rebuilt these ideas more clearly:

- AI tools should not be understood only by brand name. They should be classified by layer: chat, development environment, terminal agent, model platform, or general assistant base.
- Hermes' strength is not replacing professional developer tools, but connecting models, tools, memory, skills, and messaging platforms into long-running workflows.
- Messaging gateways are convenient but increase permission and accidental-trigger risks, so whitelists, wake words, role isolation, and human confirmation matter.
- Skills turn repeated tasks into reusable workflows, which is closely connected to maintaining a learning repo, knowledge base, and personal workflow.
- Qy Knowledge Hub's core value is turning external information into reviewable data first, then into trusted knowledge assets, without letting external platforms control the system.
- The ZK trading system note reminded me that an onchain trading system is not a single-technology problem. It is a system problem across proofs, witness data, sequencing, oracles, DA, cost, and user behavior.
