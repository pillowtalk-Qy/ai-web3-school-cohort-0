## Hackathon Direction / 黑客松方向

今天虽然主要工作是整理和部署笔记，但这些笔记都在服务同一个方向判断。

我现在更清楚了三件事：

1. 方向不能只是“AI + wallet + security + payment”几个大词堆在一起。
2. demo 必须有一个很具体的 review surface。
3. 边界必须写进产品，而不是写在说明里。

这几篇笔记共同把我的方向往这里推：

```text

-> one review surface
-> deterministic facts
-> wallet policy boundary
-> human confirmation
-> audit proof
```

今天更强烈的判断是：

- 黑客松 demo 要像 VC 说的那样先有最小闭环。
- 也要像 Base MCP 那样保留最终用户批准。
- 还要像 Hermes / 本地模型讨论里说的那样，把 AI 放在合适的一层，而不是让它承担所有责任。

English companion:

Today's note work still pushed the hackathon direction forward. The project needs one review surface, deterministic facts, a real policy boundary, human confirmation, and audit proof. The more I read, the clearer it becomes that the demo must be small, bounded, and easy to explain.
