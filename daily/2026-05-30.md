今天的 Hackathon 策划围绕一个核心问题：

从昨天的 weekly meeting 来看，这个方向有潜在交集：

- 我的方向已经围绕 wallet permission、agent payment、policy check、human confirmation 和 audit proof 展开。
- Week 2 final deliverable 已经把 `AI Wallet Clear Intent Guard` 收束成 pre-signing review layer。
- Harness engineering 的讨论也提醒我，demo 不应该只展示 AI 解释，还应该展示工具边界、权限边界和失败路径。

目前更适合第一版 demo 的范围是：

```text
User or agent intent
-> candidate wallet action or payment request
-> deterministic facts
-> wallet policy check
-> AI review card
-> human confirmation
-> mock execution or audit proof
```

中文表达：

```text
用户或 Agent 意图
-> 候选钱包动作或支付请求
-> 确定性事实
-> 钱包策略检查
-> AI 审查卡片
-> 人工确认
-> mock 执行或审计 proof
```

第一版 demo 不做完整钱包，也不连接真实私钥或真实资产。更适合在以下三个 review surface 中选一个：

- `ERC-20 approve mismatch`：用户只想授权少量 token，但交易事实是无限授权。
- `x402 payment request review`：Agent 看到 payment request 后，检查 payee、resource、amount、network、token 和 budget。
- `authority package review`：用户授予 Agent 某段时间、某预算、某对象范围内的能力，系统解释边界并标记越权。

今天的倾向是：先不要扩大范围。等 2026-06-01 正式赛道要求出来后，再决定是否把 demo 主线压到 Cobo Agentic Wallet / agent economic。

English companion:

The hackathon direction still points to `AI Wallet Clear Intent Guard`: a small pre-signing review layer for intent, deterministic facts, wallet policy, and audit proof. The first demo should pick one review surface and make it clear, rather than trying to build a full wallet.
