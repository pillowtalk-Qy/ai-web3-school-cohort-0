### Demo Flow and Technical Framework / Demo 流程与技术框架

今天也把这次 Demo 的流程和实现技术大框架理清了一轮。

前几天的学习材料已经逐渐收束成一个结构：

```text
Mandate
-> Packet
-> Payment
-> Guard review
-> User confirmation
-> Audit proof
```

今天的推进是把这个结构变成更接近 Demo 的流程：

- 用户给出任务目标和预算边界。
- Agent 根据任务准备执行或支付请求。
- Guard 抽取可审查事实。
- Guard 对比用户 intent、预算、权限范围和 payment / packet facts。
- 系统标记 risk level，并解释为什么需要通过、提醒或阻止。
- 用户在签名或执行前做确认。
- Demo 保留一条可展示的 proof / audit trail。

实现技术的大框架也更清楚了：

- 前端需要展示任务、Agent 提议、Guard review card、风险解释和确认结果。
- 后端或本地逻辑需要承接 intent comparison、policy check、mock-safe facts 和 demo state。
- AI 负责解释、对比和生成可读 review，不负责直接签名或绕过确认。
- Web3 / wallet 相关部分优先保持安全边界，必要时用 mock-safe 数据展示流程。

English companion:

I also clarified the Demo flow and the high-level implementation framework. The current direction is a review flow around Mandate, Packet, Payment, Guard review, user confirmation, and audit proof. AI explains and compares; deterministic policy checks provide boundaries; wallet-related execution should remain mock-safe unless the team explicitly confirms a safer integration path.
