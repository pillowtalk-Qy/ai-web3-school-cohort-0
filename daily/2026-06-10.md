## What I Did / 今日完成

### Demo Framework Completed / Demo 框架设计完成

今天最主要的进展，是把整个 Demo 的框架基本设计完。

前几天项目已经逐步收束到 pre-signing review layer。今天进一步把它整理成一条可以展示、可以解释、明天可以继续跑通的 Demo 路径：

```text
User intent
-> Agent proposal
-> Transaction / Packet facts
-> Guard review
-> Risk state
-> Human confirmation
-> Audit proof
```

这个结构的重点不是做一个完整钱包，而是展示 AI wallet / Agent wallet 在签名前最需要补上的一层：

```text
Does the proposed action actually match what the user meant?
```

中文来说，就是用户说出的意图、Agent 生成的动作、链上交易事实三者之间，必须有一层清楚的审查和暂停机制。

今天完成的框架里，Demo 不再只是一个抽象想法，而是有了更明确的展示顺序：

- 先出现用户 intent。
- 再出现 Agent 准备执行的 proposed action。
- 然后显示结构化 facts / Packet。
- Guard 进行一致性检查和 policy check。
- 页面输出 `Looks consistent`、`Needs review` 或 `Do not sign`。
- 用户做最后确认或拒绝。
- 系统生成 mock audit proof，表示这次审查路径被记录。

English companion:

The biggest progress today was finishing the Demo framework. The Demo is now organized as a clear pre-signing review path: user intent, agent proposal, transaction / Packet facts, Guard review, risk state, human confirmation, and audit proof. The goal is not to build a full wallet, but to show the missing safety layer before signing.

### Technical Language Completed / 技术语言设计完成

今天另一个重要工作，是把项目的技术语言整理得更清楚。

之前项目里有很多正确但偏技术的词：

```text
intent
Packet
clear signing
policy check
pre-signing review
audit proof
human confirmation
```

这些词如果直接堆给评委或普通用户，会显得像技术说明书，而不是产品 Demo。今天把它们重新整理成更容易讲清楚的表达：

- `User intent`：用户真正想做什么。
- `Agent proposal`：AI / Agent 准备替用户发起什么动作。
- `Transaction facts`：交易实际包含什么内容。
- `Guard review`：签名前审查层如何对比意图和事实。
- `Risk state`：这笔操作看起来一致、需要复核，还是不建议签名。
- `Human confirmation`：最终签名边界仍然回到用户。
- `Audit proof`：保留一份可追溯的审查记录。

今天重新确认了技术表达的核心句子：

```text
AI can help explain and compare, but it should not silently cross the signing boundary.
```

中文表达是：

```text
AI 可以帮助解释和对比，但不能越过用户直接完成签名边界。
```

这句话会成为 Demo 叙事里的关键锚点。它既解释了为什么需要这个产品，也说明了项目的安全边界。

English companion:

I also finished the technical language for the Demo. Instead of throwing raw technical terms at judges, the project should explain the flow in plain language: what the user meant, what the agent proposed, what the transaction contains, how the Guard compares them, what the risk state is, and why final confirmation remains with the user.
