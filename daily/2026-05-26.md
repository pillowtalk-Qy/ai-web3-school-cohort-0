这节课的核心问题是：

```text
如何让 AI Agent 在可控边界内操作链上资产？
```

课程中最重要的风险提醒包括：

- Silent Override / 静默覆盖：用户只看到“成功”，但 Agent 实际执行金额或动作可能偏离原始意图。
- Privacy Custody / 隐私托管或外溢：Agent 可能绕开 MPC 钱包，自建地址并把资金移出原控制边界。
- Prompt 注入：模型被诱导执行未授权交易。
- Shadow Operations / 影子操作：Agent 创建隐藏子账户或执行路径。
- Unscoped Authority / 无边界授权：Agent 获得过大权限。
- Zombie Permissions / 僵尸授权：授权长期不撤销，风险持续存在。

我整理出的 Cobo 三层方案是：

1. MPC 私钥安全架构：Agent 不直接拿完整私钥。
2. Packed Authority：把 intent、execution plan、policy、completion condition 封装成可审阅授权边界。
3. Recipe Skill Layer：通过预先验证的协议操作路径减少模型临时构造和幻觉。

My main takeaway: agent wallet safety cannot rely on the model being obedient. It needs an execution-layer authority package: scoped authority, policy checks, completion conditions, auditability, and a recovery path back to human control.

## Rebuilt Understanding / 重新建立的理解

- AI × Web3 不是把 AI 和链拼在一起，而是要找到“AI 负责理解 / 解释 / 协调，Web3 负责权限 / 支付 / 结算 / 验证”的真实交叉点。
- Wallet / Permission / Safe Execution 是我目前最适合深挖的主线，因为它连接了课程任务、黑客松方向、Cobo 课程、x402 payment 和 Agent Memory。
- Agent wallet safety 需要区分三层：
  - 当前交易事实。
  - 授权包和 policy 边界。
  - 长期身份、声誉、记忆和历史权限。
- Packed Authority / Pack 的启发是：用户不应该只看一笔 calldata，而应该看到 intent、execution plan、policy、completion condition 和风险标记。
- Payment / Commerce 不是“付钱”一个动作，而是一条商业链路：报价、预算授权、执行、交付、验收、付款、退款、争议和 proof。
- x402 和 ERC-8004 是互补的：x402 回答支付和结算，ERC-8004 回答 agent identity / reputation / validation。
- 公开学习 repo 的价值在于形成连续 proof surface：每天的 note、task proof、class note、meeting note 和 WCB 状态都能互相引用。

- AI x Web3 should be understood through real division of labor: AI handles understanding, explanation, and coordination; Web3 handles authority, payment, settlement, and verification.
- Wallet / Permission / Safe Execution is currently my strongest main line.
- Agent wallet safety has at least three layers: current transaction facts, authority / policy boundary, and long-term identity / reputation / memory / permission history.
- A Pack-like design suggests that users should review intent, execution plan, policy, completion condition, and risk, not only raw calldata.
- Payment / Commerce is a full flow, not just a payment action.
- x402 and ERC-8004 are complementary rather than substitutes.
