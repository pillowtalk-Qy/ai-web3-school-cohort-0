## 5. AI + Wallet Brainstorming / AI + 钱包落地方向头脑风暴

### Safety Monitoring and Auto Transfer / 安全监控与自动转移资产

讨论中有人提出：

```text
AI monitors wallet transfer anomalies
-> detects abnormal transaction
-> automatically moves assets to a backup wallet
```

这个方向表面上很有安全价值，但风险也非常大：

- AI 控制资产权限会形成黑箱。
- 模型底层依赖可能引入不可控风险。
- 一旦被攻击，自动转移逻辑本身可能变成盗转通道。
- 用户很难判断 AI 何时应该真的移动资产。

我的理解是，这个方向不适合直接做成“AI 自动接管资产”。更安全的版本应该是：

```text
detect anomaly
-> explain risk
-> propose action
-> require explicit policy or human confirmation
-> record audit proof
```

### Small-Budget Agent Finance / 小额授权理财

讨论中也提到一种方向：

- 用户设置小额资金授权额度，例如固定预算。
- AI Agent 做行情分析或量化策略。
- 钱包负责执行理财相关操作。

这个方向的可行性取决于：

- 预算边界是否清楚。
- 风险提示是否足够。
- 交易策略是否可解释。
- 执行权限是否可撤销。
- 是否能避免暗示收益保证。

公开笔记不把它写成投资建议。

### Intelligent Account Management / 智能账目管理

另一类方向是：

- 自动梳理链上资金流水。
- 分析持仓和账目。
- 对资产涨跌做风险提醒。

讨论中也指出，这类方向可能不一定必须用 AI，因为链上流水可以直接导出和结构化处理。AI 的价值需要落在解释、分类、提醒和用户理解上，而不是重复做已有数据导出功能。

### Small-Amount No-Sign or Pre-Authorized Payment / 小额免签或预授权支付

讨论中较有落地价值的方向是：

```text
fixed scenario
-> fixed budget
-> small amount
-> pre-authorized rule
-> simplified repeated confirmation
```

这类方向比“AI 全自动管理资产”更可控，因为它可以把权限边界写清楚：

- 场景固定。
- 金额固定或有上限。
- 对象范围可限定。
- 时间范围可限定。
- 超出边界必须重新确认。

这与 `AI Wallet Clear Intent Guard` 的方向非常接近。

English companion:

The wallet brainstorming made one point clear: letting AI freely control funds is risky. A safer product direction is pre-authorized, small-scope action with explicit budget, scenario, time, counterparty, and audit boundaries.

## 6. SUCCB / Cloud Code Desk Bridge Project / SUCCB 项目介绍

### Basic Positioning / 基本定位

会议中介绍了一个赛道 2 参赛项目：

```text
Cloud Code Desk Bridge
```

简称记录为：

```text
SUCCB / CCB
```

项目定位是：

```text
AI engineering collaboration open-source framework
```

中文理解：

```text
一个把 AI 写作 / AI coding 从零散对话，转成可控、可复用、可审计工程过程的协作框架。
```

### Pain Points / 痛点

会议中提到的现有 Agent 开发问题包括：

- 多窗口并发开发需要频繁切换页面。
- 任务会话记录零散。
- 步骤不可视。
- 故障节点难以定位。
- 长流程出错后回滚困难。
- 上下文堆积容易引发 hallucination。
- Token 资源消耗高。

### Core Design / 核心设计

项目采用双 Agent 分工：

```text
Call = decision maker
Code = executor
```

Call 负责：

- 需求解析。
- 技术方案设计。
- 任务拆分。
- 内容审核。

Code 负责：

- 代码落地。
- 执行任务。
- 根据 Call 的方案推进实现。

两者可以双向沟通，校验方案漏洞，模拟现实软件工程中的多人协作。

### Standardized Process / 标准化流程

SUCCB 试图把零散灵感式 AI 对话，变成：

```text
protocol
-> task node
-> approval
-> execution
-> archive
-> audit evidence
```

这对长任务很重要，因为长任务最怕：

- 中间状态丢失。
- 上下文重复堆积。
- 错误无法追踪。
- 结果不可复用。

### Cost and Token Efficiency / 成本与 Token 效率

会议中提到，项目希望通过模型分工降低成本：

- 高成本模型用于方案决策。
- 低成本模型承担代码落地。
- 避免每一步都使用高成本模型。
- 避免通过不断追加 Markdown 造成上下文冗余。

这个思路和 Agent 工程化非常相关：真正的成本优化不是只换便宜模型，而是减少无效上下文、重复传递和不可审计流程。

### Track Fit / 赛事适配

根据会议讨论，SUCCB 与赛道 2 的适配点包括：

- 长任务执行。
- 工具调用。
- 迭代修复。
- 成果交付。
- 过程记录。
- 可拓展到 Web3 合约开发或通用软件工程。

具体是否满足赛道要求，仍需以 ZAI / 赛道 2 官方规则为准。

English companion:

SUCCB / Cloud Code Desk Bridge is an AI engineering collaboration framework. Its core idea is to split planning and execution between agents, reduce token waste, make long workflows auditable, and preserve task evidence. This is relevant to long-horizon task execution.

## My Understanding / 我的理解

这次 co-learning 对我自己的黑客松方向很有帮助，因为它把“AI + 钱包”的风险说得更具体了。

我现在更不想做：

```text
AI detects risk
-> AI directly moves user assets
```

这个路径太容易踩到权限黑箱、攻击面扩大和用户失控的问题。

我更想做的是：

```text
user intent
-> transaction/payment facts
-> policy boundary
-> AI explanation
-> human confirmation or pre-authorized small action
-> audit proof
```

也就是说，`AI Wallet Clear Intent Guard` 的关键不是让 AI 变成资产管理员，而是让 AI 帮用户和钱包系统看清楚：

- 当前动作是否符合用户意图。
- 当前动作是否在权限边界内。
- 当前动作是否超出预算、场景、对象或时间范围。
- 哪些信息必须由用户再次确认。
- 哪些记录应该作为审计 proof 保存。

这和 Cobo 赛道可能关注的钱包流程优化、智能化、权限控制和真实使用体验更接近。

English companion:

This session clarified what I should avoid: an AI that directly takes over user assets. A better direction is a permission-aware wallet review layer. AI can explain and compare, but policy boundaries and human confirmation should remain explicit.

## English Summary

The co-learning session discussed agent learning resources, hackathon registration, model subscription and reimbursement, Cobo track interpretation, AI wallet product ideas, and the SUCCB project.

For my own hackathon direction, the key takeaway is that AI wallet products need careful permission boundaries. The risky version is AI directly moving assets. The safer version is a wallet review and policy layer where AI explains intent and risk, wallet policy enforces limits, and humans retain confirmation rights.

The SUCCB project also offered a useful engineering lesson: long AI workflows need visible steps, role separation, approval nodes, archives, and audit evidence. That thinking can also inform how a wallet review demo records its decision path.
