## Session Overview / 课程概览

本次 co-learning 内容主要围绕几个问题展开：

- 如何用人工学习和 Agent 辅助学习两种方式完成课程。
- 打卡、任务、学分和平台记录之间如何区分。
- Week 1 到 Week 4 的整体学习安排。
- 6 月初黑客松的方向、组队方式和作品要求。
- AI + Web3 项目如何选题、调研和避免重复造轮子。

The session focused on how to study manually or with Agent assistance, how task submissions and daily check-ins differ, the four-week course structure, hackathon planning, team formation, and project direction selection.

## 一、学习方式与资料说明

课程学习可以分成两种模式。

### 1. 人工学习

人工学习包括：

- 参与平台活动。
- 完成课程任务。
- 学习课程内容与参考资料。
- 阅读老师整理的模块材料。

课程每个模块都配有较充分的资料，可以支撑系统学习。对学习者来说，人工学习仍然是理解概念、形成判断和做取舍的基础。

### 2. Agent 辅助学习

Agent 辅助学习侧重把资料阅读、部署实践、记录整理和任务拆解交给 AI 工具辅助完成。

现场提到的 Hammurabi Agent 部署资料包括三类核心参考：

- Dragon 老师在良心道的教程视频回放，推特可看。
- 公开页面的文字版 recap，方便 AI 读取和处理。
- 学员分享的 permission agent 部署文章与仓库。

配套资料还包括指定 digg prompt，中英双语版本，以及中文区 API 接入指南。API 接入指南覆盖概念澄清、自我定位、Deepseek / Qwen 方案、AI coding 选择、API key 安全准则和常见问题。

## 二、课程任务与打卡解耦规则

### 核心规则

打卡失败只代表“财富共学打卡”未通过，不影响继续在平台学习、完成任务或参与活动。打卡和 WCB 平台任务属于两个独立板块。

这点很重要：不要把一次打卡失败理解成课程失败。真正应该持续推进的是学习、任务 proof、活动参与和项目实践。

### 拓展学习资源

课程每周下方会附带大量任务和参考资料，可以作为无限拓展学习入口。

开源 Handbook 支持这些方向：

- AI 基础。
- Web3 基础。
- AI x Web3 交叉方向。
- 前沿方向。

Handbook 首页提供精简版 roadmap，点击知识点可以定向学习。Handbook 是 GitHub 开源仓库，学员可以提交 PR 进行补充、修正和优化。

### 英文直播听不懂怎么办

现场提到两个方案：

- 付费方案：Immersive Translate。它是知名翻译软件，但免费功能较少，不一定支持视频实时翻译。
- 免费方案：Chrome 浏览器内置 accessibility 实时字幕 / 翻译功能。

## 三、整体课程安排

课程节奏大致如下：

| Week / 周次 | Focus / 重点 |
|---|---|
| Week 1 | AI 基础 + Web3 基础 |
| Week 2 | AI 与 Web3 结合逻辑、交叉理论、Web3 devtools 融合 AI 等交叉基础 |
| Week 3 | 前沿方向学习、交叉实战课程、启动黑客松 |
| Week 4 | 纯黑客松，黑客松第二阶段 |

我的理解是，Week 1 是共同语言建设，Week 2 开始进入 AI 与 Web3 的交叉结构，Week 3/4 则逐步转向真实项目和黑客松产出。

## 四、黑客松安排

### 时间

黑客松预计在 6 月初启动，现场提到的时间点是 6 月 1 日左右。进群学员会收到通知。有想法的学员可以提前组队筹备，已有学员开始做 demo。

### 赛道方向

核心赛道包括：

- Agentic commerce。
- 钱包工具。
- 安全治理。

也会有 open track，不属于核心方向的项目可以归入开放赛道。

### 项目要求

黑客松不只是要求 demo 能跑通，也希望项目具备持续开发潜力。

现场强调了两种目标：

- 如果目标是冲奖金，需要优化 pitch 展示和前端体验。
- 如果目标是长期发展，需要重视落地可行性、用户价值和可行性研究。

现场也提到有孵化机构、VC 和 Web2 / Web3 投资机构关注课程与黑客松，但这类信息应以官方后续说明为准，不能在笔记中理解成对单个项目的投资承诺。

### 配套支持

黑客松期间会开设 code building 支持，邀请实战老师讲解技巧，并帮助解答 debug 问题。

## 五、学分与打卡说明

### 打卡分值

现场提到单次打卡为 40 分，约等于 4 个常规活动的分值。有些活动可能只有 5 分，相当于需要更多活动才能达到同等分值。

### 打卡目的

打卡的核心不是机械完成任务，而是记录学习感受、想法和真正学到的内容。

### 学分作用

学分主要用于：

- 激励学习。
- 引导学习节奏。
- 作为学员 showcase 的一部分。
- 帮助项目方发现人才。

黑客松记录也会纳入 showcase。

### 打卡异常

如果无法打卡，可以尝试退出重新登录，并同步让助教协助排查。仓库未同步打卡记录时，以平台显示为准。

## 六、黑客松组队技巧

### 自我定位

组队前先明确自己是否有 idea、是否要担任 leader。

如果不是 leader：

- 明确自己的优势。
- 找缺少对应能力的团队加入。
- 不要只等待别人招募。

如果是 leader：

- 明确项目需要什么能力。
- 识别自己的短板。
- 针对性招募队友。

### 沟通原则

组队要真心换真心，最好带着想法、材料或初步 demo 去交流。

现场特别提醒，不建议使用“白嫖式”表达，例如只说明身份或背景，然后等待别人给机会。团队也不是人越多越好，人数和能力组合应该匹配项目需求。

## 七、技术问题与项目指导

### 1. AI 操控钱包方向

现场建议不要从零开发插件钱包，因为工程量很大。

更现实的路径是参考成熟 agentic wallet 方案，例如 Cobo Agent Wallet，并查看其开发者文档和原生 SDK 集成能力。

也可以关注 OKX、Stripe 等机构在 agent wallet 或 AI payment 方向的布局。

### 2. Web3 社群 / 创客项目

现场提到 OPC 相关方向时，提醒先调研市面上已有成熟产品，例如 NCC 数字游民社区的小程序“游牧岛”，它支持项目发起、个人主页、投票、社群互动和求职等功能。

建议先调研同类产品，在已有方案基础上创新，避免重复开发。可以用 AI 定向查询 OPC 相关社区项目。

### 3. AI + Web3 优质项目查找

现场提到的标杆项目包括：

- AGDP：agentic commerce 领域参考项目。
- Virtuals：Base 链上的头部 agent 应用。

信息渠道包括 AI 查询、X / Twitter、GitHub 和项目官网。

现场判断是，AI + Web3 领域仍处早期、不够成熟，因此机会很多，也有可能做出超越现有项目的产品。

### 4. 黑客松作品查看

可以通过项目 X / Twitter、GitHub、官网，以及主办方公开的获奖项目页面查看参考作品。

也鼓励复用自己的过往项目，持续迭代优化，而不是每次从零开始。

## 八、其他重要事项

### 学员分享

每周五会举办学员分享，鼓励学员分享学习内容和自我展示。参与分享可以获得 5 学分奖励。

### 风险提醒

现场提醒要警惕“发盘割机器人”等灰色项目。这类项目的核心问题不在技术实现，而在用户、合规和价值观边界。

对本课程来说，更值得投入的是 AI + Web3 的正规建设方向，例如钱包安全、权限控制、身份验证、Agent 工具、开发者工具和可验证学习记录。

### 平台互动

英文区学员可以在聊天框提问或开麦交流。

课程也鼓励学员对 Handbook 提 PR，共同完善学习资料。

## 九、现场问答要点

整理后的问答要点：

- Web2 转 Web3 找标杆项目：优先看 Virtuals、AGDP，关注 Base 链生态，也可以用 AI 定向检索。
- 项目作品复用：可以复用自己的黑客松作品，在本次黑客松中继续迭代升级。
- 打卡异常处理：退出重登，联系助教协助排查，以平台显示状态为准。

## My Understanding / 我的理解

这次 co-learning 对我最有帮助的是，它把“学习、打卡、任务、黑客松、组队、项目落地”放到了一条完整链路里。

几个关键理解：

- 打卡和任务是不同系统。打卡失败不等于学习失败，真正重要的是持续产出可验证的学习记录。
- Handbook 和课程资料不是一次性读完的材料，更像一个长期 roadmap，可以随着项目需要反复检索。
- Agent 辅助学习的重点不是让 AI 代替思考，而是让它帮助处理资料、脚本、部署、摘要和 proof 准备。
- 黑客松项目不能只追求“能跑”，还需要问题真实、范围可控、边界安全、有持续开发可能。
- AI 操控钱包、自动化交易、Agent 执行链上动作都必须保持谨慎，优先复用成熟方案，并保留人工确认。

## English Summary

This co-learning session explained how to use both manual learning and Agent-assisted learning in AI x Web3 School. It clarified that daily check-ins and WCB course tasks are separate systems, introduced the course roadmap from Week 1 to Week 4, and gave more detail about the upcoming hackathon.

The strongest practical guidance was around scope control. For hackathon projects, a running demo is not enough; the project also needs a real problem, a clear user scenario, safety boundaries, and some potential for continued development. For team formation, learners should understand their own role and bring concrete ideas or skills instead of passively waiting to be recruited.

For AI x Web3 project directions, the session suggested studying agentic commerce, wallet tools, security governance, Cobo Agent Wallet, Virtuals, AGDP, and Base ecosystem projects. It also warned against gray-area bot projects and encouraged learners to focus on legitimate AI + Web3 building.

My main takeaway is that Agent-assisted learning should reduce friction, not replace judgment. AI can organize materials, summarize docs, help with deployment, and prepare proof text, but wallet actions, asset movement, contract writes, public publishing, and WCB submission still require explicit human confirmation.
