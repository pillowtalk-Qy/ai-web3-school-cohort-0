## 1. Speaker A: Open Source Contribution and Web3 Career Growth

### Open Source as an Accessible Entry Point / 开源作为低门槛入口

Speaker A 强调，开源贡献的一个重要优势是：

```text
open source is accessible 24/7
```

它不要求固定时间、固定地点或高强度社交。对不太喜欢团队沟通、比较害羞、或者还在建立信心的人来说，开源是很好的切入口。

我的理解是，开源对 Web3 学习者有三层价值：

- 它让学习者可以用自己的节奏进入真实代码库。
- 它让贡献记录公开可查，而不是只停留在简历描述。
- 它让维护者看到你是否真正理解项目，而不只是会讲概念。

### GitHub and Hiring / GitHub 与求职

Speaker A 提到，专业技术招聘者在看候选人时，会非常重视 GitHub。一个维护良好的 GitHub，比只写 LinkedIn 简历更能证明真实能力。

特别是在 Web3 里：

- 项目更开源。
- 贡献记录更可见。
- 维护者更倾向于信任熟悉代码库的人。
- 贡献过 cool projects 的人更容易被看见。

English companion:

Open source gives builders public proof of work. In Web3 hiring, GitHub can carry more weight than a polished profile because it shows actual contribution, consistency, and familiarity with real codebases.

## 2. Increasing Visibility and Opportunity / 提升可见度与机会

### Public Speaking / 公开分享

Speaker A 鼓励初学者也可以从本地 meetup 开始分享。分享不一定要等到“完全准备好”，它本身就是建立 credibility 的过程。

公开分享的价值包括：

- 帮助自己整理知识。
- 让别人知道你在关注什么方向。
- 为项目或社区带来更多可见度。
- 可能吸引合作伙伴、投资人或未来机会。

一条可行路径是：

```text
local meetup
-> focus on one field
-> become known for that topic
-> get invited to larger or global events
```

### Community Mentor / Monitor / 社区角色

Speaker A 提到，可以主动承担 academy monitor、mentor 或类似社区角色。不要因为觉得自己“不够资格”就不尝试。

我的理解是，这类角色的价值不只是头衔，而是：

- 接触更多全球成员。
- 更快理解社区需求。
- 建立长期信任。
- 在帮助别人时巩固自己的学习。

### Event Volunteering / 活动志愿者

Speaker A 认为，做志愿者通常比只是参加活动更能建立深连接。志愿者会接触组织者、嘉宾、项目方和其他主动参与者，这些连接的长期有效性可能超过单次活动本身。

English companion:

Visibility can be built through local talks, community roles, and volunteering. These are not only promotion tactics; they are ways to build trust through repeated contribution.

## 3. Success Cases from Open Source and Building in Public

Speaker A 分享了几个案例，用来说明 open source、building in public 和 community support 如何改变职业路径。

### Case 1: Public Personal-branding Example

Speaker A 提到一个公开建设个人品牌的案例：这位 builder 在失业后持续公开分享求职经验、帮助别人进入行业、积累连接，后来获得 Web3 社交 / 社区相关岗位机会。

这对我的启发是：

```text
building in public 不只是展示成果，也可以展示学习过程、失败经验、求职经验和对他人的帮助。
```

### Case 2: Web2-to-Web3 Builder

另一个案例是从 Web2 转入 Web3 的 builder。这个人通过开源贡献进入特定生态，成为 core contributor，获得 fellowship 等机会，并继续做更专业的 Web3 项目。

公开笔记中只保留职业路径层面的启发：

- 非线性背景不一定是弱点。
- 真正的贡献可以重新定义别人如何看你。
- 公开可验证的贡献比“我想转行”更有说服力。

### Case 3: DeFi Open-source Contributor

另一个案例是通过开源贡献获得 DeFi 方向的发展机会。

这说明对想进入某个细分赛道的人来说，持续贡献可以成为比泛泛学习更有效的路径。

### Case 4: Student Community Builder

Speaker A 提到一位学生 builder 的案例：这位同学在大学时期缺少设备，但在社区表达了参与意愿和现实困难。社区后来提供支持，他继续建设多个项目，创办学生区块链社区，并参与更多区域活动。

这个案例最重要的不是“获得设备”，而是：

- 公开表达真实需求。
- 社区愿意支持真诚参与者。
- 被帮助之后继续建设并回馈社区。

English companion:

The shared cases show that building in public can include job-seeking notes, open source work, community building, and helping others. The strongest pattern is not sudden luck, but visible contribution plus trust.

## 4. Key Web3 Ecosystem Principles / Web3 生态原则

Speaker A 提到两个关键原则：

### Give Back to the Community / 回馈社区

如果曾经从社区获得帮助，就应该在有能力时帮助别人。这样社区才能持续，而不是变成单向索取。

我的理解是，Web3 社区的长期生命力来自：

- 资源共享。
- 经验传递。
- 新人支持。
- 公开贡献。
- 被帮助者成为新的帮助者。

### Build Trust / 建立信任

Speaker A 强调，trust 在 Web3 生态中非常重要。

这和我这周的 wallet / permission / governance 主线也有关：技术上可以用 proof、onchain record、open source 和 audit log 增强可信度，但人与人之间的长期信任仍然来自持续贡献和一致行为。

English companion:

The ecosystem depends on a give-back loop. Trust is built through repeated contribution, public records, and helping others after receiving help.

## 5. Q&A: AI, Web3, Personal Branding, and Career Choice

### Question 1: If Starting Today, AI, Web3, or AI + Web3?

Speaker B 问：如果今天重新开始职业路径，会选择 AI、Web3，还是 AI + Web3？

Speaker A 的答案是：

```text
AI + Web3
```

原因包括：

- Web3 更 permissionless，可以不依赖闭源平台独立建设项目。
- AI 显著提高开发效率。
- 未来可能进入 agent economy，AI agents 使用 Web3 的频率可能超过人类。
- builder 需要想清楚产品到底服务 humans 还是 agents。
- 纯 AI 产品容易依赖第三方闭源平台，平台变化会影响项目可持续性。

我的理解是，AI + Web3 的交叉点不只是“用 AI 写 Web3 代码”，而是：

```text
AI 提高构建效率和交互能力；
Web3 提供开放执行、身份、支付、权限和可验证记录。
```

### Question 2: Personal Branding for Early Builders

Speaker B 问：早期 builder 的个人品牌有多重要，如何实操？

Speaker A 的回答是：非常重要。

可行步骤：

1. 加入有结构化项目的社区，例如有 learning path 和 partner resources 的 community。
2. 在社区里完成项目，最好能展示在 GitHub。
3. 参与开源贡献，积累经验、可见度和信任。

Speaker A 也提到，中文 Web3 社区有非常活跃的开源贡献者，这是一种优势。

### Question 3: Cold Outreach Without Response

Speaker B 问：如果给导师或陌生人 cold outreach 没有回复怎么办？

Speaker A 的建议：

- 有 mutual connection 时更容易获得回复，因为别人可以确认你不是 scammer。
- 优先联系熟人介绍的人。
- 社区外陌生联系更难。
- 也可以在项目 Discord 开 support ticket，尝试联系团队。

English companion:

Speaker A would choose AI + Web3 today because Web3 is more permissionless and AI improves building speed. Personal branding matters early, but the practical path is structured community participation, completed projects, GitHub proof, and open source contribution.

## 6. Q&A: From Design Background to Full-stack Builder

Speaker D 背景偏艺术和设计，想成为 full-stack builder，但担心工程能力、框架能力和代码质量不足。

问题是：

```text
如何学习工程分层和 programming taste？
```

Speaker A 的建议包括：

- 把设计能力和基础 Web coding 结合起来。
- 继续使用 Figma、视频编辑和视觉表达优势。
- 不要完全依赖 AI 生成设计，仍要保留自己的判断。
- 用 Cursor、VS Code 等工具提升开发效率。
- 对简单项目，直接使用成熟框架，不要从零搭所有东西。
- 可以使用特定生态开发框架，例如现场提到的 Nuwa AI / Solana development framework，但这类工具需要后续按官方资料核验。
- 遇到具体需求时，带着明确问题去找人指导。

我的理解是，设计背景进入 full-stack 的优势不应该被抹掉。更好的路径不是“变成纯工程师”，而是：

```text
design taste + AI-assisted coding + mature frameworks + focused engineering basics
```

English companion:

For design-background builders, the goal is not to erase design taste. A practical path is to combine design ability with basic Web coding, AI-assisted tools, mature frameworks, and targeted engineering fundamentals.

## Relation to My AI x Web3 Direction / 和我当前方向的关系

这次分享和我的 `AI Wallet Clear Intent Guard` 方向有三处连接。

第一，开源贡献和公开 proof 很重要。我的项目如果继续推进，应该尽早把 demo、设计文档、风险边界和测试样例公开整理好。

第二，AI + Web3 的核心机会之一是 agent economy。我的方向正好围绕 agent payment、wallet permission、human confirmation 和 audit proof 展开。

第三，trust 是 Web3 生态的核心。一个钱包 review tool 不只是要“看起来聪明”，还要能证明：

- 它用什么事实判断。
- 它不能做什么。
- 谁负责。
- 如何撤销。
- 如何审计。
- 何时必须交给人。

English companion:

This session connects directly to my current direction. A wallet review tool needs open proof, clear non-capabilities, accountability, revocation, auditability, and human confirmation. Trust is the product requirement, not only a community value.
